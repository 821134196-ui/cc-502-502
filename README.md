# 可循环周转箱台账

工厂把可循环周转箱按箱型、箱号、押金和出库批次发给客户；客户返箱后检查
**箱体 / 封盖 / 标签**，合格箱重新入库，破损箱进维修池或报废。系统覆盖数量
不足、箱号归属、跨批次返还、押金争议、维修费用、长期未返六类异常的明确处置。

零第三方依赖：Python 3 标准库（`sqlite3` + `http.server`）+ 原生前端。

## 一条命令启动

```bash
./run.sh            # 初始化并播种（含混批返箱样例），启动在 http://127.0.0.1:8000
./run.sh --reset    # 清空重建演示数据
./run.sh 8080       # 指定端口
```

启动后打开 http://127.0.0.1:8000 ，左下角切换角色：**仓库 / 财务 / 管理员**。

## 页面

| 页面 | 内容 |
|---|---|
| 总览 | 在客户处（应返）、维修池、逾期、押金池余额 |
| 客户箱账 | 按客户汇总，点击行展开到**逐箱台账**与事件流 |
| 发箱扫描 | 选客户/箱型/数量/应返期，生成出库批次，逐箱收押金 |
| 返箱验收 | **应返 / 实返 / 待修同屏**；扫码逐箱勾选三项检查，**折抵金额紧挨验收结论**；可拍破损照片 |
| 维修池 | 仓库“修完回库”、财务“确认折抵 / 豁免” |
| 逾期清单 | 长期未返箱，财务核销并转赔偿 |
| 押金流水 | 逐箱 CHARGE/REFUND/抵扣/应收，争议登记与处理 |

界面采用工业白（`#f4f6f8`）、深灰侧栏（`#2f3540`）与清晰绿色状态标记（`#1f9d63`）。

## 关键规则

- **返箱扫描与押金抵扣同一箱号**：每条抵扣/退款流水都 `box_id` 挂账，返箱回执逐箱列示。
- **并发退箱不扣两次**：`BEGIN IMMEDIATE` + 状态条件更新
  `UPDATE boxes ... WHERE id=? AND state='OUT'`，第二个并发请求得到
  `ALREADY_RETURNED`；同一返箱集 `set_ref` 重放幂等。
- **角色限制**：仓库只能操作实物（发箱、验收、修完回库）；财务只能折抵复核、
  逾期核销、押金争议。越权返回 `403 FORBIDDEN`。
- **折抵待复核**：维修/报废抵扣先挂“待财务复核”，不计入押金余额；财务可确认
  （改金额）或豁免。金额单位为整数分。维修费/赔偿费超出押金部分转**应收款**。
- **异常留痕**：箱号不属于客户 `NOT_OWNED`、跨批次未放行 `CROSS_BATCH`、
  重复退箱 `ALREADY_RETURNED` 均在 `exceptions` 表记录，不产生任何资金动作。

## 混批返箱样例（华东生鲜连锁 C01）

一次扫码含两个批次：`R60-00006` 合格入库（B20260901）、`R60-00007` 破损送修
（折抵待复核）、`R80-00001` 合格入库、`R80-00002` 报废（赔偿待复核，均为
B20260915）；另含两个被拒箱号：`R60-00009` 属北辰物流（NOT_OWNED）、
`R60-00006` 重复退箱（ALREADY_RETURNED）。另有 1 单未决押金争议、7 个逾期箱。

## 数据与适配器

- SQLite：`data/turnover.db`，逐箱事件表 `box_events` + 押金流水 `deposit_ledger`。
- 破损照片：随验收上传，落盘 `data/photos/`。
- 财务回执：**模拟适配器** `app/finance.py`，把每批验收/复核/核销/争议回执写
  `data/finance_receipts/<ref>.json` 并入库（按 ref 幂等）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：箱号归属、重复退箱（含两线程并发）、`set_ref` 幂等、跨批次拒收/放行、
折抵与扫描箱号一致、待复核→确认/豁免的余额一致性、赔偿超押金转应收、
仓库/财务/管理员角色限制、HTTP 端到端（含照片上传与 403）。

## 目录

```

app/server.py    零依赖 HTTP（JSON API + 静态页 + 照片）

app/web/         前端（index.html / styles.css / app.js）
tests/           领域与 HTTP 测试
run.sh           一条命令
```
